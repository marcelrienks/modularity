## Output Directory Structure

```
./output/                              # Default or user-specified --output-dir
├── handle_d2.6_h2.0.stl              # Generated model (STL format)
├── handle_d2.6_h2.0.step             # Generated model (STEP format, if --format step/both)
└── handle_d2.6_h2.0_README.md        # Assembly guide (auto-generated)

# Multiple generations with different parameters
├── handle_d3.0_h1.5.stl
├── handle_d3.0_h1.5_README.md
├── handle_d2.2_h2.5.stl
└── handle_d2.2_h2.5_README.md
```

## Filename Encoding Scheme

### Format

```
handle_d{diameter}_h{height}.{ext}
```

| Component | Rule | Example |
|-----------|------|---------|
| `diameter` | Float as user input; no rounding | `d2.6`, `d3.0`, `d2.25` |
| `height` | Float as user input; no rounding | `h2.0`, `h1.5`, `h0.75` |
| `ext` | File extension | `stl`, `step` |

### Examples

| User Input | Filename |
|------------|----------|
| `--diameter 2.6 --height 2.0` | `handle_d2.6_h2.0.stl` |
| `--diameter 3.0 --height 1.5` | `handle_d3.0_h1.5.stl` |
| `--diameter 2.25 --height 0.875` | `handle_d2.25_h0.875.stl` |

**Precision**: Input floats preserved exactly; no truncation or rounding in filename.

## File Format Specifications

### STL (Stereolithography)

- **Binary format** (ASCII optional, binary preferred for size)
- **Triangle mesh** representing watertight 3D geometry
- **Encoding**: 3D coordinates in mm (SI unit, consistent with input parameters)
- **Integrity**: Mesh must be closed (no open edges), no self-intersections
- **Typical size**: 40–80 KB per handle model (density-dependent)

**Generated by**: CadQuery `Shape.exportStl(filepath)`

**Validation**: 
- File size > 0 bytes
- Binary header validates (80-byte header + facet count)
- Successful import back into CadQuery (re-parse test)

### STEP (Standard for the Exchange of Product Data)

- **Format**: AP214 (automotive/design standard)
- **Geometry**: Solid body representation with parametric history
- **Encoding**: Units in mm (SI standard)
- **Precision**: Full double-precision coordinates
- **Integrity**: Watertight solid with no defects

**Generated by**: CadQuery `Shape.exportStep(filepath)`

**Validation**:
- File size > 0 bytes
- STEP header validates (ISO 10303-21)
- Successful import back into CadQuery

### Assembly Guide (Markdown README)

**File**: `handle_d{diameter}_h{height}_README.md`

**Format**: Standard GitHub-flavored Markdown

**Structure**:
```markdown
# Handle d{diameter}mm h{height}mm

## Specifications
- Diameter: {diameter} mm
- Height: {height} mm
- Generated: {ISO 8601 timestamp}
- Base geometry: ToolGrid modular system

## Print Settings (PLA Default)
- Nozzle temperature: 200–210°C
- Bed temperature: 60°C
- Print speed: 40 mm/s
- Layer height: 0.2 mm
- Infill: 20% (grid pattern)
- Supports: None (design optimized)

## Assembly
1. Print STL file on FDM 3D printer
2. Inspect for layer uniformity and overhangs
3. Attach to ToolGrid via magnetic interface
4. Insert tools using grip diameter

## Troubleshooting
- Grip too loose? → Re-generate with +0.2mm diameter
- Grip too tight? → Re-generate with -0.1mm diameter
- Layer separation? → Increase nozzle temp by 5°C
- Failed adhesion? → Check bed calibration

## Technical Details
- Material: PLA (or PETG recommended for durability)
- Grid compatibility: 10mm hole spacing (standard ToolGrid)
- Thermal expansion: Account for 1–2% shrinkage post-print
```

**Content Generation**: Jinja2 template + parameter substitution

## Output Behaviors

### File Overwrites

**Scenario**: User runs generator twice with same `--diameter` and `--height`

**Behavior**:
1. Script detects existing file at target path
2. Prompts: `"File exists: ./output/handle_d2.6_h2.0.stl\nOverwrite? [y/N]: "`
3. User enters 'y'/'yes' → Overwrites file
4. User enters 'n'/'no'/empty → Aborts, exits code 4

**No Auto-Append**: Does NOT generate `handle_d2.6_h2.0_1.stl` or similar variants.

### Output Directory Auto-Creation

**Scenario**: `--output-dir ./custom_folder` where custom_folder doesn't exist

**Behavior**:
1. Attempt to create directory (and parents if needed, like `mkdir -p`)
2. Success → Continue with generation
3. Failure (permissions, etc.) → Exit with error message, code 3

### STL vs. STEP Comparison

Both formats should represent **identical geometry**:
- Same triangle/surface mesh (within floating-point precision)
- Same dimensions (diameter × height)
- Same mounting interface
- No geometry differences based on export format

**Used for**:
- **STL**: 3D printing (slicer tools, FDM printers)
- **STEP**: CAD refinement (modify, combine with other parts), engineering review

## Validation Checklist

After file creation, implementation must verify:

- [ ] STL file size > 0 and ≤ 500 KB
- [ ] STEP file size > 0 and ≤ 1 MB
- [ ] Filenames follow `handle_d{d}_h{h}.{ext}` exactly
- [ ] Assembly guide markdown is valid and renders correctly
- [ ] Re-import test passes (CadQuery can parse exported file)
- [ ] No partial files on error (clean exit)
- [ ] Timestamps in README are accurate
