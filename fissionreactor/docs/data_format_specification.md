# Data Format Specification

Complete specification of all JSON data formats used by fissionreactor.

## Overview

The fissionreactor workflow produces and validates 7 JSON files following strict schemas. These files form an **AI-ready context package** containing both design geometry and design intent.

### File Chain

```
[Fusion 360 Export]
         ↓
    model.json (exported design)
         ↓
    [Questionnaire]
         ↓
    context.json (design intent)
         ↓
    [Transform]
         ↓
    ├─ metadata.json (model info + intent)
    ├─ parameters.json (code generation ready)
    ├─ constraints.json (validation rules)
    ├─ features.json (feature timeline)
    └─ assembly.json (component structure)
```

## 1. model.json - Design Export

**Source:** Fusion 360 (via `export_fusion360_data.py`)  
**Schema:** `schemas/model.schema`  
**Required:** YES  
**User Editable:** NO (generated by export script)

### Purpose
Captures complete design geometry, parameters, and feature timeline from Fusion 360.

### Key Sections

#### export_metadata (required)
```json
{
  "version": "1.0",
  "exported_date": "2026-01-27T09:00:00Z",
  "source_file": "ShelfBracket_v1.f3d",
  "fusion360_version": "2.0.x",
  "export_method": "fissionreactor_add_in"
}
```

**Fields:**
- `version` (string): Schema version for format tracking
- `exported_date` (ISO 8601): When export happened
- `source_file` (string): Original .f3d filename
- `fusion360_version` (string): Fusion 360 version used
- `export_method` (string): How export was performed

#### model (required)
```json
{
  "name": "ShelfBracket_v1",
  "description": "Corner bracket for modular shelving",
  "part_count": 1,
  "body_count": 1,
  "feature_count": 12,
  "parameter_count": 8
}
```

**Fields:**
- `name` (string, required): Model identifier
- `description` (string): Human-readable description
- `part_count` (integer, required): Number of parts
- `body_count` (integer): Number of bodies
- `feature_count` (integer): Total features
- `parameter_count` (integer): User-defined parameters

#### parameters (required, array)
```json
[
  {
    "name": "BaseWidth",
    "type": "length",
    "value": 200,
    "unit": "mm",
    "min": 100,
    "max": 300,
    "step": 10,
    "used_in_features": ["Base Extrude", "Rib Spacing"],
    "note": "Controls shelf width"
  }
]
```

**Per-Parameter Fields:**
- `name` (string): Parameter name (PascalCase convention)
- `type` (enum): One of `length`, `angle`, `text`, `integer`, `real`
- `value` (number/string): Current/default value
- `unit` (string): Measurement unit (mm, degrees, etc.)
- `min` (number): Minimum valid value
- `max` (number): Maximum valid value
- `step` (number/null): Recommended increment for variations
- `used_in_features` (array): Which features use this parameter
- `note` (string): Optional notes

#### features (required, array)
```json
[
  {
    "name": "Base Extrude",
    "type": "extrude",
    "order": 0,
    "description": "Creates base platform",
    "parameters": ["BaseWidth", "BaseDepth", "BaseThickness"],
    "depends_on": [],
    "sketch": "BaseProfile"
  },
  {
    "name": "Mounting Boss",
    "type": "extrude",
    "order": 5,
    "description": "Raised mounting point",
    "parameters": ["BossHeight"],
    "depends_on": [0],
    "sketch": "BossSketch"
  }
]
```

**Feature Timeline Fields:**
- `name` (string): Feature name as shown in Fusion 360
- `type` (enum): Feature type (extrude, pocket, hole, fillet, chamfer, etc.)
- `order` (integer): Position in feature timeline (0-indexed)
- `description` (string): What this feature does
- `parameters` (array): Parameter names used in this feature
- `depends_on` (array): Feature indices this depends on
- `sketch` (string): Associated sketch name

#### components (optional, array)
```json
[
  {
    "name": "BaseBody",
    "parent": "root",
    "feature_count": 8,
    "sketch_count": 3
  }
]
```

#### sketches (optional, array)
```json
[
  {
    "name": "BaseProfile",
    "plane": "XY",
    "constraints": 12,
    "geometry_items": 8
  }
]
```

#### timeline (optional, array)
Complete chronological feature list with relationships.

## 2. context.json - Design Questionnaire

**Source:** Questionnaire (user-filled version of `questionnaire_template.json`)  
**Schema:** `schemas/questionnaire.schema`  
**Example:** `examples/questionnaire.json`  
**Required:** YES  
**User Editable:** YES

### Purpose
Provides design intent, constraints, materials, and planned variations. **This is what AI uses to understand WHY the design was made.**

### Key Sections

#### context_metadata (required)
```json
{
  "model_name": "ShelfBracket_v1",
  "version": "1.0",
  "author": "John Designer",
  "creation_date": "2026-01-20",
  "last_modified": "2026-01-27T15:30:00Z"
}
```

- `model_name` (string, required): Must match model.json name
- `version` (string): Model version
- `author` (string): Designer name
- `creation_date` (string): YYYY-MM-DD format
- `last_modified` (string): ISO 8601 timestamp

#### purpose
```json
{
  "purpose_primary": "Support shelf on modular post system",
  "purpose_use_case": "Residential shelving system",
  "purpose_context": "Connects vertical aluminum posts to horizontal wooden shelves"
}
```

- `purpose_primary` (string): Main purpose
- `purpose_use_case` (string): Specific application
- `purpose_context` (string): Context in which used

#### design_intent
```json
{
  "intent_critical_features": "Load-bearing mounting points must be strong",
  "intent_design_decisions": "Used corner brackets for maximum rigidity",
  "intent_trade_offs": "Aesthetic curves sacrificed for structural strength"
}
```

#### dimensions
```json
{
  "dimension_primary": "Width (controls other dimensions)",
  "dimension_relationships": "Height = 0.25 * Width, Thickness = 0.05 * Width",
  "dimension_scale": "150-300mm typical range"
}
```

#### constraints
```json
{
  "constraint_tolerances": "Mounting holes: ±0.5mm for M3 bolts",
  "constraint_minimum": "Wall thickness minimum 1.5mm or parts break",
  "constraint_maximum": "Width limited to 300mm by post spacing",
  "constraint_rules": "Fillets must be ≥1mm for 3D printing reliability",
  "constraint_dependencies": "Boss height = 15% of width"
}
```

**Note:** These constraints must be EITHER all filled OR all empty. If mixing, you'll get a warning.

#### materials
```json
{
  "material_type": "3D printed plastic (PLA/ABS)",
  "material_properties": "Moderate strength, good detail resolution",
  "fabrication_process": "FDM 3D printing",
  "fabrication_limitations": "Min wall 1.5mm, detail resolution 0.4mm"
}
```

#### assembly
```json
{
  "assembly_sub_components": "Two mounting bosses, one base platform",
  "assembly_structure": "Single-part monolithic design",
  "assembly_instructions": "No assembly - single 3D printed part",
  "assembly_difficulty": "Simple",
  "assembly_fasteners": "M3 bolts and washers for shelf mounting"
}
```

#### variations
```json
{
  "variations_family": "Small/Medium/Large shelf brackets",
  "variations_parameters": "BaseWidth varies (S:150mm, M:200mm, L:250mm)",
  "variations_count": 3
}
```

## 3. metadata.json - Unified Model Info

**Source:** Generated by `transform_metadata.py`  
**Schema:** `schemas/metadata.schema`  
**Required:** YES (generated)  
**User Editable:** NO

### Purpose
Consolidates model info + design intent into single reference file.

```json
{
  "metadata": {
    "version": "1.0",
    "generated_date": "2026-01-28T10:15:30Z",
    "model_name": "ShelfBracket_v1",
    
    "model_info": {
      "name": "ShelfBracket_v1",
      "description": "Corner bracket for modular shelving",
      "part_count": 1,
      "feature_count": 12,
      "parameter_count": 8
    },
    
    "design_intent": {
      "purpose": "Support shelf on modular post system",
      "use_case": "Residential shelving",
      "critical_features": "Load-bearing mounting points",
      "design_decisions": "Corner brackets for rigidity"
    },
    
    "context": {
      "author": "John Designer",
      "creation_date": "2026-01-20",
      "version": "1.0"
    },
    
    "export_source": {
      "source_file": "ShelfBracket_v1.f3d",
      "export_date": "2026-01-27T09:00:00Z",
      "fusion360_version": "2.0.x"
    }
  }
}
```

## 4. parameters.json - Code Generation Ready

**Source:** Generated by `transform_metadata.py`  
**Schema:** `schemas/parameters.schema`  
**Required:** YES (generated)  
**User Editable:** NO

### Purpose
Specifies all parameters with CLI argument names, types, ranges, and validation for code generation.

```json
{
  "parameters": {
    "version": "1.0",
    "generated_date": "2026-01-28T10:15:30Z",
    "model_name": "ShelfBracket_v1",
    
    "parameters": [
      {
        "name": "BaseWidth",
        "cli_name": "--base-width",
        "type": "float",
        "default": 200,
        "min": 100,
        "max": 300,
        "unit": "mm",
        "description": "Shelf width in millimeters",
        "validation": "Must be multiple of 10, >= 100, <= 300"
      },
      {
        "name": "BaseThickness",
        "cli_name": "--base-thickness",
        "type": "float",
        "default": 10,
        "min": 8,
        "max": 12,
        "unit": "mm",
        "description": "Material thickness",
        "validation": "Range 8-12mm for structural integrity"
      }
    ]
  }
}
```

**CLI Integration Example:**
```bash
python generate_shelfbracket.py --base-width 250 --base-thickness 10
```

## Validation Rules

### All Files
- Must be valid JSON (no trailing commas, proper quotes)
- All string IDs must be unique within their scope
- No sensitive data should be included

### model.json
- `name` must match source .f3d filename (without extension)
- Each parameter must have unique name
- Feature orders must be consecutive (0, 1, 2, ...)
- Feature dependencies must reference valid order indices
- All features in `depends_on` must have lower order index

### context.json
- `model_name` must match model.json name
- If any constraint field is filled, either all must be filled OR fill ONLY the required ones
- Questionnaire should cover all design aspects

### Generated Files (metadata, parameters, constraints, features, assembly)
- Auto-generated from model.json + context.json
- All contain same `model_name` for traceability
- All contain `generated_date` timestamp
- Version field allows future format changes

## Using Schemas for Validation

### Programmatic Validation
```python
import jsonschema

schema = json.load(open('schemas/model.schema'))
model = json.load(open('model.json'))

try:
    jsonschema.validate(model, schema)
    print("✓ Valid")
except jsonschema.ValidationError as e:
    print(f"✗ Invalid: {e.message}")
```

### Command-Line Validation
```bash
# Using ajv (Node.js)
ajv validate -s schemas/model.schema -d examples/model.json

# Using python-jsonschema
python -m jsonschema.cli schemas/model.schema examples/model.json
```
